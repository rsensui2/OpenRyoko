# cron設定と実行登録の同期

`cron/jobs.json` の一覧と、スケジューラに登録されたジョブは別の状態です。Issue #75への対応として、ファイル監視・定期照合・登録状態の表示を追加しています。

- `jobs.json` の親ディレクトリで追加・変更・削除を検知します。短時間に続く変更はまとめて読み込みます。
- 監視イベントが届かない場合も、30秒ごとに設定と登録を照合します。監視エラーはログに残します。
- 同じ内容のジョブは再登録しません。待機中の実行を定期照合で取り消したり、二重登録したりしません。
- JSONの読み込み失敗・不正な形式・重複ID・ファイル消失は空のジョブ一覧と区別します。最後の正常な登録を保持し、正常なファイルが戻れば次のイベントまたは定期照合で復旧します。
- スケジュールやタイムゾーンが不正なジョブは登録エラーとして表示し、正常な他のジョブは継続します。
- APIからの保存は同じディレクトリの一時ファイルへ完成したJSONを書き、renameで置換します。壊れたファイルをAPIから空の一覧として上書きすることも防ぎます。

通常の変更にはダッシュボードまたは認証付きAPIを利用してください。直接編集する場合、すべての定期実行を解除するには有効な空配列 `[]` を保存します。ファイルの削除だけでは最後の登録が維持されます。

## 確認方法

`GET /api/cron` は従来どおり配列を返し、各ジョブに `scheduler` を追加します。

| state | 意味 |
|---|---|
| `scheduled` | 現在の設定で定期実行に登録済み |
| `disabled` | 無効で、実行登録もない |
| `pending` | ファイルの設定が未反映。`registered: true` なら旧設定で登録中 |
| `error` | スケジュール等の問題で登録できない。`error` に理由を表示 |
| `stopped` | スケジューラが停止している |

`GET /api/cron/status` は、スケジューラの稼働状態、登録ID、最後の反映時刻、設定ファイルの読み込み可否、未反映のジョブID、設定から削除されたのに登録が残るジョブIDを返します。設定が読み取れなくても、この診断APIは利用できます。

ジョブ一覧の読み込みに失敗すると `GET /api/cron` は503を返します。画面は前回取得した一覧であることと、現在の読み込みエラーを表示します。

この修正は、報告された「2日以上イベントが届かなくなる」現象のOS側の原因を特定するものではありません。イベントが欠落しても復旧できる経路を設けています。登録前に過ぎた実行時刻を遡って実行する機能はありません。
