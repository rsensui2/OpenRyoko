# Claude Code / Codex の双方向フォールバック

通常のSlack等の会話とWebの会話で、Claude Code・Codexのどちらが利用上限、空応答、無応答になっても、もう一方へ引き継げる。

```yaml
engines:
  claude:
    fallback: [codex]
  codex:
    fallback: [claude]
sessions:
  rateLimitStrategy: fallback
  engineNoResponseTimeoutMs: 300000
```

未設定時は上の双方向経路と5分の無応答期限を使う。既存の `sessions.fallbackEngine` はClaude側の既定経路として引き続き使える。`engines.<engine>.fallback` が明示されていれば優先し、空配列 `[]` はそのエンジンからの切り替えを止める。登録済み・設定済みの代替だけを試す。1ターン中に同じエンジンを再試行しないため、両側が制限中でも往復し続けない。

ダッシュボードの設定 → セッション →「利用上限・無応答時の動作」で切り替えと待機を選べる。`rateLimitStrategy: wait` は自動切り替えを行わず、利用上限の解除を待つ。空応答・無応答の場合はエラーになる。CLI認証やAPI契約を代替側にも準備しておく必要がある。代替側がログインしていなかった場合は切り替えを取り消し、そのエンジンを30分のあいだ代替から外す。

解除を待つのは、リセットが6時間以内の場合と、時刻が分からない場合（最長6時間）。リセットが6時間より先と分かっている利用上限は、待たずに失敗し、エラーにリセットの時刻が入る。切り替え先が無い場合も `wait` の場合も同じ。待っている間に gateway が再起動しても、次の起動で、リセットの10秒後に続きを実行する。

無応答期限は実際のストリーム出力・上流通信の活動で更新する。接続が開いたままという事実だけでは期限を延ばさない。Claude の headless エンジンは、CLI が出力した行をすべて活動に数え（差分にならない思考やツール入力の途中経過も含む。keep-alive の行は除く）、実行中のツールと背景で動くエージェントも活動として扱う。interactive（PTY）エンジンは、上流通信に加えて、ツールの PreToolUse から PostToolUse／PostToolUseFailure までを活動として扱う。どちらも、ツールかタスクが最後に始まるか終わってから15分を過ぎたら止まったとみなし、それ以外の活動だけで判断する（`packages/jimmy/src/engines/claude-activity.ts`）。`engineNoResponseTimeoutMs: 0` は追加の無応答監視を無効にする。タイムアウトで元プロセスの停止を確認できなければ、同時に同じ仕事を実行するのを避けるため代替を起動しない。

宛先側のモデル・思考設定・MCP設定を使い、別プロバイダのモデルIDやCLI固有フラグを渡さない。`fallbackModelMap` が設定されていれば有効な対応モデルを選ぶ。各エンジンの会話IDと直近の会話、失敗した試行の途中の回答・ツール進行の概要を上限付きで引き継ぐ。ツールの引数・結果本文を新たな診断情報に残さない。切り替え先には実行済みの作業を確認してから続けるよう伝える。

利用制限はリセット時刻まで（最長12時間。それより先のリセットは、12時間たった時点で元エンジンを試し直す。時刻不明なら6時間）、無応答は5分の一時的な切り替えとして扱う。その後のターンで元エンジン・モデル・思考設定に戻し、代替中の会話も補完する。利用上限の記録が先に消えた場合（元エンジンがターンを返した、再確認で枠が開いていた）は、期限を待たずに戻す。

あるエンジンが利用上限中と記録されている間、そのエンジンを使うはずだった新しいセッションは、失敗するターンを挟まずに代替エンジンで始まる（コネクタ経由も `POST /api/sessions` も同じ）。エンジンやモデルを名指しした呼び出し、`rateLimitStrategy: wait`、ワークフローの試行、`sshHost` の社員は対象外。記録は `GET /api/status` の `engines.<名前>.health` で確認できる。ユーザーの停止・セッションのリセット・意図的な沈黙・正常終了したネイティブコマンドの空結果は切り替え理由にしない。

Jevの未依頼の提案は単発応答とし、そこからゴールを自動抽出したり、保留中のゴールを再開したりしない。既存のゴール自体は保持する。通常の依頼でフォールバックする場合は、ゴールの所有者と状態を保って引き継ぐ。
