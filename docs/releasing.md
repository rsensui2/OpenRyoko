# Public release notes

Write release notes for people installing or upgrading OpenRyoko: features, behavior changes, usage, compatibility, and reproducible validation. Attach only public product screenshots, documentation, checksums, and package artifacts.

Keep deployment reports private. Do not include instance or container names, account identifiers, personal filesystem paths, hostnames, internal jobs or channels, private operating statistics, or whether an individual installation was deployed successfully. General Docker instructions and CLI compatibility information are appropriate when they help users upgrade.

Inspect attachment contents and metadata as well as the release body. Keep checked-in release notes consistent with the public GitHub Release. Report private deployment completion separately to the requesting user.
